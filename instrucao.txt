================================================================================
  InoLabel - Installation and Usage Guide
  New to this? Follow the steps in order.
================================================================================

INTRODUCTION IN 30 SECONDS
--------------------------
InoLabel is a desktop tool for annotating images and videos with:
  • Bounding boxes
  • Tracking (following objects across frames)
  • OBB (oriented bounding boxes — rotated boxes)
  • Keypoints (pose)
  • Classification (organizing images into categories)

Choose a folder of images, define classes, annotate in your web browser,
and export in YOLO or COCO format. Everything runs locally — no data leaves
your machine.

VERSION: 2.0.0 (FastAPI + React + Vite)
PLATFORMS: Windows 10+ or Linux (Ubuntu/Debian)

See README.md for the main reference and AGENTS.md for implementation rules.
The interface currently uses Portuguese labels; quoted labels below match the app.


BEFORE YOU START
----------------
Install the following tools in order. After installing each one, CLOSE and
REOPEN YOUR TERMINAL so it can find the new commands.

Estimated setup time: 30–45 minutes, depending on your connection.

  WINDOWS 10/11
  -------------

  1. Git (2.40+)
       Download: https://git-scm.com/download/win
       Install with the default options.
       Close PowerShell and open a new window.
       Check: git --version
       Example output: git version 2.45.0

  2. Node.js (20 or newer; CI uses 22)
       Download: https://nodejs.org
       Install with the default options.
       Close PowerShell and open a new window.
       Check: node --version
       Check: npm --version

  3. Miniconda
       Download: https://docs.conda.io/en/latest/miniconda.html
       Choose the Windows 64-bit installer.
       Open an Anaconda Prompt or Miniconda Prompt after installation.
       Check: conda --version

  4. Visual C++ Build Tools and CMake
       Required to compile lap and cython-bbox.
       Download: https://visualstudio.microsoft.com/visual-cpp-build-tools/
       Select "Desktop development with C++" in the installer.
       Download CMake: https://cmake.org/download/
       Select "Add CMake to the system PATH" during installation.

  LINUX (Ubuntu / Debian and derivatives)
  --------------------------------------

  1. Update and install system dependencies:
       sudo apt-get update
       sudo apt-get install -y git curl build-essential python3-dev cmake libgl1 libglib2.0-0 zenity

       Package purposes:
       • build-essential, python3-dev, cmake: compilers and build tools
       • libgl1, libglib2.0-0: libraries used by OpenCV
       • zenity: native folder picker on GNOME (use kdialog on KDE)

       Install Node.js 20 or newer from nodejs.org or through nvm.
       Distribution packages may provide an older version.
       Check: node --version
       Check: npm --version

  2. Install Miniconda (Python environment manager):
       curl -fsSL https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -o miniconda.sh
       bash miniconda.sh -b -p $HOME/miniconda3
       source $HOME/miniconda3/etc/profile.d/conda.sh
       conda init

       Close and reopen the terminal afterward.
       Check: conda --version


STEP 0: DOWNLOAD THE PROJECT (ONCE)
-----------------------------------
If you do not already have the project, clone it once.

  WINDOWS (PowerShell or Command Prompt):
    Choose a folder, such as C:\Projects or C:\Dev.
    cd C:\Projects
    git clone https://github.com/Inovisao/InoLabel.git
    cd InoLabel

  LINUX (terminal):
    mkdir -p ~/projects
    cd ~/projects
    git clone https://github.com/Inovisao/InoLabel.git
    cd InoLabel

  This downloads:
    • Application source code
    • Build scripts in scripts/ (build.ps1 and build.sh)
    • Python dependency declarations (requirements.txt)
    • Web interface source code (frontend/)


================================================================================
  PART 1: WINDOWS - BUILD AND RUN
================================================================================

STEP 1 - Navigate to the project folder
--------------------------------------
  Open PowerShell or Command Prompt:
    cd C:\Projects\InoLabel

  Use the actual path where you cloned the project.
  Check that these paths exist:
    - main.py
    - frontend/
    - scripts/build.ps1


STEP 2 - Build the frontend (web interface)
------------------------------------------
  Run in this order:
    cd frontend
    npm ci
    npm run build
    cd ..

  What each command does:
    • npm ci installs Node.js packages from the lockfile.
    • npm run build compiles React + Vite and creates the dist folder.

  Read warnings and errors. An unsupported Node.js version must be fixed
  before continuing.

  Check that frontend\dist\index.html exists alongside JavaScript/CSS assets.


STEP 3 - Build the executable
----------------------------
  The Windows script checks the environment, creates the inolabel conda
  environment if needed, installs dependencies, builds the frontend,
  and packages the application with PyInstaller.

  From PowerShell, at the project root:
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
    .\scripts\build.ps1

  From Command Prompt:
    powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1

  Estimated time: 15–30 minutes, depending on the connection and hardware.
  Keep the terminal open until the build finishes.


STEP 4 - Locate the executable
-----------------------------
  Output:
    APLICATIVO\InoLabel\InoLabel.exe

  Bundle layout:
    APLICATIVO\
    └── InoLabel\
        ├── InoLabel.exe         ← Run this file
        ├── _internal\           ← Internal dependencies; keep these intact
        ├── dataset\             ← Optional location for your source images
        ├── outputs\             ← Default output location when none is specified
        └── model.pt             ← Optional YOLO model

  Keep the entire bundle together when moving it to another machine.
  The bundle can occupy 1.5–3 GB; the executable file alone is not the full app.


STEP 5 - Prepare images and videos
---------------------------------
  You can place data in:
    APLICATIVO\InoLabel\dataset\

  Example:
    dataset\
    ├── img1.jpg
    ├── img2.png
    └── video.mp4

  Supported formats:
    Images: .jpg, .jpeg, .png, .bmp, .tif, .tiff
    Videos: .mp4, .avi, .mov, .mkv

  Optionally place trusted YOLO weights at:
    APLICATIVO\InoLabel\model.pt

  Model inference is optional. See README.md for current inference support.


STEP 6 - Run the application
---------------------------
  Option A — PowerShell:
    cd C:\Projects\InoLabel\APLICATIVO\InoLabel
    .\InoLabel.exe

  Option B — File Explorer:
    Navigate to C:\Projects\InoLabel\APLICATIVO\InoLabel
    Double-click InoLabel.exe.

  Allow time for startup. The browser should open at:
    http://127.0.0.1:8765

  If the browser does not open, check the terminal for startup errors.
  Once the server is running, open that address manually.


STEP 7 - Use InoLabel
--------------------
  On first launch:
    1. Choose a workspace folder for your projects.
    2. Choose an annotation mode:
       • Detection — independent bounding boxes
       • Tracking — object IDs maintained across frames
       • OBB — rotated bounding boxes
       • Keypoints — named points per class
       • Classification — images organized by class
    3. Choose your data folder and enter a project name.
    4. Define classes and colors. For keypoints, define ordered point names.
    5. Start annotation.

  During annotation:
    • Click and drag to draw a box.
    • Use Left / Right arrows or A / D to navigate frames.
    • Press V to select or move annotations.
    • Press Delete to remove a selected annotation.
    • Press N to mark a frame as reviewed without objects.
    • Press Ctrl+Z to undo.
    • Open the export dialog with Ctrl+E or the top toolbar.

  Changes are saved after each operation. Use "Projetos → Continuar"
  to resume an existing project. See README.md for mode-specific controls.


STEP 8 - Export data
--------------------
  After annotating frames:
    1. Open the dataset export dialog.
    2. Choose YOLO and/or COCO, according to the annotation mode.
    3. Configure train/validation/test proportions if splitting is enabled.
    4. Optionally enable training data augmentation.
    5. Choose a destination and start the export.

  The default destination is the project's exports/ folder.
  Export runs in the background with a progress bar.
  Existing unrelated directories are protected against deletion.


STEP 9 - Stop the application
----------------------------
  In the terminal running InoLabel:
    Ctrl+C

  For a packaged app without an accessible terminal, use Task Manager:
    Ctrl+Shift+Esc → InoLabel.exe → End task


================================================================================
  PART 2: LINUX - BUILD AND RUN
================================================================================

STEP 1 - Navigate to the project folder
--------------------------------------
    cd ~/projects/InoLabel

  Use the actual clone location. Check that main.py exists:
    ls -la main.py


STEP 2 - Build the frontend
--------------------------
    cd frontend
    npm ci
    npm run build
    cd ..

  Check the result:
    ls -la frontend/dist/index.html


STEP 3 - Prepare Python and build the executable
------------------------------------------------
  Create and activate the supported Python environment:
    conda create -n inolabel python=3.9 -y
    conda activate inolabel
    pip install -r requirements.txt

  From the project root:
    bash scripts/build.sh

  The script checks build prerequisites and packages the application with
  PyInstaller. The frontend must already be built.
  Keep the terminal open until the build finishes.


STEP 4 - Locate the executable
-----------------------------
  Output:
    dist/InoLabel-linux/InoLabel/InoLabel

  Bundle layout:
    dist/InoLabel-linux/InoLabel/
    ├── InoLabel              ← Run this file
    ├── _internal/            ← Internal dependencies; keep these intact
    ├── dataset/              ← Optional source data location
    ├── outputs/              ← Default output location when none is specified
    └── model.pt              ← Optional YOLO model

  Check:
    ls -la dist/InoLabel-linux/InoLabel/InoLabel


STEP 5 - Prepare images and videos
---------------------------------
  You can copy source images into the bundle's dataset folder:
    mkdir -p dist/InoLabel-linux/InoLabel/dataset
    cp /path/to/images/* dist/InoLabel-linux/InoLabel/dataset/

  Supported formats:
    Images: .jpg, .jpeg, .png, .bmp, .tif, .tiff
    Videos: .mp4, .avi, .mov, .mkv

  Optional trusted YOLO weights:
    cp /path/to/model.pt dist/InoLabel-linux/InoLabel/model.pt


STEP 6 - Run the application
---------------------------
    cd ~/projects/InoLabel/dist/InoLabel-linux/InoLabel
    ./InoLabel

  The browser should open at http://127.0.0.1:8765.
  If it does not, check terminal errors, then open the address manually
  once the server is running.


STEP 7 - Annotate and export
---------------------------
  Follow Steps 7 and 8 in Part 1. The workflow is the same on both systems.


STEP 8 - Stop the application
----------------------------
  In the terminal running InoLabel:
    Ctrl+C


================================================================================
  PART 3: RUN FROM SOURCE (WITHOUT PACKAGING)
================================================================================
  Use this workflow to test or edit the app without creating an executable.
  Python 3.9 is the version used by the project's CI and pinned environment.

  STEP 1 - Create and activate an environment
  ------------------------------------------
    conda create -n inolabel python=3.9 -y
    conda activate inolabel

  STEP 2 - Install Python dependencies
  -----------------------------------
    pip install -r requirements.txt

    Downloads can be large because the environment includes PyTorch.

  STEP 3 - Build the frontend
  --------------------------
    cd frontend
    npm ci
    npm run build
    cd ..

    Rebuild after changing frontend source files when using this workflow.

  STEP 4 - Run
  ------------
    python main.py

    The app serves the compiled interface at:
      http://127.0.0.1:8765

    Stop with Ctrl+C in the terminal.

  DEVELOPMENT WITH AUTO-RELOAD
  ---------------------------
    For backend and frontend editing, use separate terminals.

    Backend (Linux shell):
      INOLABEL_ENV=development python main.py

    Backend (Windows PowerShell):
      $env:INOLABEL_ENV = "development"
      python main.py

    Frontend (another terminal, from the project root):
      cd frontend
      npm run dev

    Open http://localhost:5173.
    The frontend forwards /api requests to the backend at port 8765.


================================================================================
  TROUBLESHOOTING
================================================================================

WINDOWS
-------

Problem: conda is not recognized
  Cause: Miniconda is unavailable in the current terminal.
  Solution:
    1. Close and reopen the terminal.
    2. Try Anaconda Prompt or Miniconda Prompt from the Start menu.
    3. Run conda --version to verify.

Problem: Set-ExecutionPolicy is not recognized
  Cause: You are using Command Prompt instead of PowerShell.
  Solution:
    powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1

Problem: npm is not recognized
  Cause: Node.js is not installed or the terminal predates the installation.
  Solution:
    1. Close and reopen PowerShell.
    2. Check node --version and npm --version.
    3. Install Node.js 20 or newer if necessary.

Problem: frontend\dist is missing
  Cause: The frontend build has not completed.
  Solution, from the project root:
    cd frontend
    npm ci
    npm run build
    cd ..

  Then run the application or build script again.

Problem: Windows blocks InoLabel.exe
  Cause: The executable is not digitally signed.
  If you trust the source and built the executable yourself, review the
  Windows "More info" dialog before choosing whether to run it.

Problem: Port 8765 is in use
  Cause: Another process is using the application's port.
  Solution: close the other InoLabel instance. If needed, locate InoLabel.exe
  in Task Manager and end that process.

Problem: The browser shows Connection Refused
  Cause: The server has not started or exited with an error.
  Solution: inspect startup errors in the terminal, verify InoLabel.exe
  is running, and retry http://127.0.0.1:8765 after startup completes.

Problem: The build takes more than 30 minutes
  Downloads and packaging can take longer on slow connections or disks.
  Keep the terminal open and inspect progress messages for actual errors.


LINUX
-----

Problem: gcc is missing or compilation fails
  Install build tools:
    sudo apt-get install build-essential python3-dev cmake

  Then retry the failed dependency installation or build.

Problem: libGL is missing
  Install:
    sudo apt-get install libgl1

  Then run the application again.

Problem: conda: command not found
  Initialize Miniconda:
    source $HOME/miniconda3/etc/profile.d/conda.sh
    conda init

  Close and reopen the terminal, then run conda --version.

Problem: Permission denied when running the executable
  Add executable permission:
    chmod +x dist/InoLabel-linux/InoLabel/InoLabel

  Then run it from the bundle folder with ./InoLabel.

Problem: The build takes more than 30 minutes
  Check the terminal output and the timestamped build log in dist/logs/.
  Slow downloads or disks can extend build time.


BOTH SYSTEMS
------------

Problem: model.pt not found
  For inference, choose an existing trusted model in the setup wizard.
  The conventional bundle locations are:
    Windows: APLICATIVO\InoLabel\model.pt
    Linux:   dist/InoLabel-linux/InoLabel/model.pt

  Manual annotation does not require a model. The interface does not yet
  include a button to start model inference; see README.md.

Problem: No images appear
  Check that the selected dataset path exists and contains supported images:
    .jpg, .jpeg, .png, .bmp, .tif, .tiff
  Verify the path selected in the wizard, preferably using an absolute path.

Problem: Dataset export fails
  Check write permissions and choose a valid export destination.
  Do not select source datasets, the project root, or protected directories.
  See README.md for destination protection rules.

Problem: Saved state cannot be read
  The app refuses to open unreadable annotations*.coco.json files.
  Restore the adjacent .bak backup or repair the JSON before resuming.

Problem: The application freezes
  Close unnecessary applications and try a smaller dataset. Check available
  memory, disk space, and terminal errors before retrying.

================================================================================
  ADVANCED USAGE
================================================================================

CHANGE THE DEFAULT OUTPUT LOCATION
---------------------------------
  INOLABEL_OUTPUT_BASE controls the fallback output location when no explicit
  output path is supplied. Workspace projects and selected export destinations
  use their own paths.

  Windows (PowerShell):
    $env:INOLABEL_OUTPUT_BASE = "C:\my_data\annotations"
    .\InoLabel.exe

  Linux:
    INOLABEL_OUTPUT_BASE="/mnt/external_disk/annotations" ./InoLabel


USE CUSTOM YOLO WEIGHTS
----------------------
  Place trusted weights in the bundle as model.pt, or select their path in
  the wizard. Only load weights from trusted sources: .pt files can execute
  code when loaded. See README.md for current inference support.


PROJECT AND EXPORT LAYOUT
-------------------------
  Project state is saved inside the workspace:

    <workspace>/<project>/
    ├── .inolabel.json
    ├── saved_data_states/
    │   └── annotations*.coco.json
    ├── labels/
    ├── classification_state.json    (classification mode)
    └── exports/

  A YOLO export can include:

    <export-folder>/
    ├── data.yaml
    ├── images/
    │   ├── train/
    │   ├── val/
    │   └── test/
    └── labels/
        ├── train/
        ├── val/
        └── test/

  Actual split folders depend on the configured proportions.
  COCO exports use the selected layout: Roboflow style or an images/ folder.

  Example training command for a detection export:
    yolo detect train data=/path/to/export/data.yaml


HARDWARE CONSIDERATIONS
-----------------------
  The previous guide's planning baseline was 4 GB RAM and 5 GB of free disk
  space; larger datasets and model inference may require substantially more.
  An SSD and 8–16 GB RAM provide more room for dependencies and image data.

  An NVIDIA GPU is optional for inference. GPU acceleration depends on a
  compatible driver and PyTorch installation; the bundled Python packages do
  not guarantee compatibility with every CUDA setup. Follow the PyTorch variant
  guidance in requirements.txt when preparing a GPU environment.
